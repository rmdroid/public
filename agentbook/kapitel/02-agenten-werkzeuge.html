Kapitel 2: Die wichtigsten Agenten-Werkzeuge ​

Clawbot, Hermes, Claude Code und Codex im Vergleich ​

Sie sind unterwegs, auf dem Weg zum nächsten Kundentermin, und Ihnen fällt ein, dass Sie eigentlich noch eine Recherche brauchen, die bis heute Abend fertig sein sollte. Sie öffnen Telegram, tippen eine kurze Nachricht und senden sie ab. Zehn Minuten später läuft die Recherche auf Ihrem Heimserver. Wenn Sie zurückkommen, wartet das fertige Briefing auf Sie.

Das ist kein Science-Fiction-Szenario. Das ist der Alltag, den Clawbot, Hermes, Claude Code und Codex in verschiedenen Formen ermöglichen. Dieses Kapitel stellt Ihnen alle vier Werkzeuge vor, erklärt, was sie können, wofür sie besonders geeignet sind, und gibt Ihnen eine klare Entscheidungshilfe.

Außerdem lernen Sie MCP kennen, das Model Context Protocol. Es ist die unsichtbare Verbindungsschicht, durch die Agenten aus dem Chatfenster heraustreten und anfangen, echte Arbeit zu erledigen.

Die wichtigste Botschaft dieses Kapitels lautet: Wählen Sie ein Werkzeug nicht nach Hype, sondern nach Arbeitsform. Ein Agent, der für Code und Dateien hervorragend ist, muss nicht der beste persönliche Assistent sein. Ein Messaging-Agent, der unterwegs nützlich ist, muss nicht die beste Wahl für riskante Schreibzugriffe auf ein Projekt sein. Und ein lernender Assistent ist nur dann ein Vorteil, wenn Sie bereit sind, seine Erinnerungen und Skills regelmäßig zu pflegen.

Die Kurzentscheidung ​

Wenn Sie nur eine schnelle Orientierung brauchen, hilft diese Matrix:

AufgabePassendes WerkzeugWarum
Aufgabe von unterwegs startenClawbot / OpenClawTelegram-Steuerung, Hintergrundlauf, eigener Server
Langfristiger persönlicher AssistentHermesMemory, Skills, wiederkehrende Routinen
Projektdateien bearbeiten und strukturierenClaude Codestarker Projektkontext, Dateiarbeit, kontrollierte Änderungen
Technische Automatisierung mit GitHubCodexstrukturierte Approvals, Sandbox, GitHub-Workflows
Externe Systeme anbindenMCP mit Claude Code oder Codexstandardisierte Werkzeugverbindung

Diese Tabelle ist keine endgültige Bewertung. Sie ist ein Einstieg. In der Praxis hängt die Wahl von drei Fragen ab: Wo liegt die Aufgabe? Welche Rechte braucht der Agent? Wie gut können Sie das Ergebnis prüfen?

Was alle vier Werkzeuge gemeinsam haben ​

Bevor Sie die Unterschiede verstehen, hilft es, den gemeinsamen Nenner zu kennen. Alle vier Werkzeuge sind KI-Agenten in dem Sinn, den Kapitel 1 beschrieben hat: Sie können Ziele entgegennehmen, Schritte planen, Werkzeuge nutzen und Ergebnisse liefern. Sie arbeiten alle mit Sprachmodellen als Kern. Und sie alle stellen die Frage, wie viel Autonomie sinnvoll ist und wo menschliche Freigabe notwendig bleibt.

Der Unterschied liegt in der Architektur, im Einsatzgebiet und im Grad der Kontrolle, den Sie als Nutzer behalten. Manche Werkzeuge sind für projektbezogene, technische Arbeit am eigenen Rechner ausgelegt. Andere sind für langfristige, persönliche Assistenz gedacht. Wieder andere glänzen als Fernsteuerung für Aufgaben, die im Hintergrund laufen sollen.

Kein Werkzeug ist für alle Aufgaben die beste Wahl. Das ist keine Schwäche dieser Werkzeuge, sondern ein Zeichen ihrer Reife. Je klarer Sie verstehen, was Sie brauchen, desto besser können Sie das richtige Werkzeug wählen.

Clawbot und OpenClaw: Der Fernbedienungs-Agent ​

Stellen Sie sich vor, Sie haben einen eigenen kleinen Server, der immer läuft. Auf diesem Server sitzt ein Agent, der Aufgaben entgegennimmt, sie ausführt und Ihnen das Ergebnis zurückschickt. Sie können ihm Nachrichten über Telegram schicken und er antwortet mit Ergebnissen, egal ob Sie am Schreibtisch sitzen, unterwegs sind oder gerade in einem Meeting.

Genau das ist das Grundprinzip von OpenClaw und seinem Vorgänger Clawbot. Die Architektur ist einfach und wirkungsvoll: Ein Telegram-Bot empfängt Ihre Nachrichten, startet auf dem Server eine Claude-Code-Sitzung in einem isolierten Docker-Container, führt die Aufgabe aus und streamt das Ergebnis zurück zu Ihnen.

Der entscheidende Vorteil dieses Ansatzes ist die räumliche und zeitliche Entkopplung. Sie müssen nicht am Computer sitzen, wenn der Agent arbeitet. Sie müssen den Agenten nicht aktiv beaufsichtigen. Und Sie können lange Aufgaben anstoßen, die deutlich mehr Zeit brauchen, als Sie normalerweise in einem einzigen Chatfenster verbringen würden.

OpenClaw wurde als einheitliche Agenten-Kontrollplattform auf einer eigenen virtuellen Maschine konzipiert. Das bedeutet, dass nicht nur einzelne Aufgaben, sondern auch geplante Briefings, semantische Suchen und Claude-Code-Sitzungen über eine gemeinsame Oberfläche steuerbar sind. Die Verbindung zu Hermes ist dabei ausdrücklich vorgesehen: Einstellungen, Erinnerungen, Skills und Konfigurationen lassen sich aus OpenClaw in Hermes importieren.

Eine wichtige praktische Einschränkung muss aber von Anfang an klar sein: Clawbot und OpenClaw sind keine fertig konfigurierten Produkte, die man mit wenigen Klicks einrichtet. Sie erfordern einen eigenen Server, technisches Grundverständnis bei der Einrichtung und konsequente Sicherheitsdisziplin. Wer diese Hürde nimmt, bekommt dafür eine Agentenumgebung, die sich nicht hinter kommerziellen Plattformen verstecken muss.

Die typische Einsatzsituation für Clawbot sieht so aus: Sie arbeiten regelmäßig von unterwegs, Sie haben Aufgaben, die länger als eine Chatssitzung dauern, und Sie wollen den Agenten nicht jedes Mal neu aufsetzen, sondern eine verlässliche Anlaufstelle haben, die immer erreichbar ist.

Was Sie dabei nie vergessen sollten: Der Server, auf dem Clawbot läuft, wird zur eigentlichen Sicherheitsgrenze. Wenn der Agent dort weitreichende Rechte hat, muss der Server selbst entsprechend abgesichert sein. Dazu mehr in Kapitel 3.

Hermes: Der lernende persönliche Assistent ​

Während Clawbot für das Starten von Aufgaben von unterwegs optimiert ist, verfolgt Hermes einen anderen Ansatz: einen Agenten zu bauen, der mit der Zeit besser wird, weil er sich an Ihre Arbeitsweise, Ihre Projekte und Ihre Vorlieben erinnert.

Hermes wurde von NousResearch als selbstverbessernder Agent mit eingebautem Lernloop konzipiert. Das ist eine mutige Beschreibung, deshalb lohnt es sich, genauer hinzuschauen, was damit gemeint ist. Hermes erstellt aus Erfahrungen sogenannte Skills, also wiederverwendbare Fähigkeitsmuster, die sich im Gebrauch verbessern. Es speichert relevante Informationen über Sitzungen hinaus, sucht in vergangenen Gesprächen und baut schrittweise ein Profil der Arbeitsweise seines Nutzers auf.

Das klingt zunächst nach einer Funktion, die einfach im Hintergrund passiert und von selbst besser wird. Die Realität ist etwas nüchterner und ehrlicher: Hermes wird besser, wenn Sie es aktiv pflegen. Skills müssen überprüft und korrigiert werden. Erinnerungen müssen regelmäßig ausgedünnt werden, damit der Agent nicht von irrelevantem Kontext überflutet wird. Und das Nutzerprofil ist nur so gut wie die Informationen, die Sie dem Agenten über Ihre Arbeit mitgegeben haben.

Dieser Pflegeaufwand ist aber auch das, was Hermes so wertvoll macht. Ein Hermes-Agent, der seit Monaten in Betrieb ist und sorgfältig konfiguriert wurde, kennt Ihre Stil-, Sprach- und Strukturpräferenzen. Er weiß, welche Projekte Sie betreuen, welche Kunden Sie haben, welche wiederkehrenden Aufgaben anfallen und wie Sie Ergebnisse strukturiert haben möchten. Das ist ein erheblicher Vorteil gegenüber einem Agenten, dem Sie jedes Mal alles von vorne erklären müssen.

Technisch ist Hermes sehr flexibel einsetzbar. Es läuft lokal, in Docker-Containern, per SSH, oder auf Cloud-Plattformen. Die Kommunikation mit Hermes ist über Telegram, Discord, Slack, WhatsApp, Signal und E-Mail möglich. Das bedeutet, Sie können Hermes in den Kanal integrieren, den Sie ohnehin täglich nutzen, ohne eine zusätzliche App öffnen zu müssen.

Die zentralen Funktionsbereiche von Hermes sind Skills, Memory, MCP-Integration, zeitgesteuerte Aufgaben über Cron, Kontextdateien und ein Messaging-Gateway. Diese Kombination macht Hermes zu einem Agenten, der nicht für einzelne Aufgaben gedacht ist, sondern für den täglichen Begleiter durch die eigene Arbeit.

Die typische Einsatzsituation für Hermes sieht so aus: Sie wollen einen Assistenten, der über Monate hinweg dazulernt, der sich an Ihre laufenden Projekte erinnert, der regelmäßig wiederkehrende Aufgaben automatisch anstößt und der über den Kanal erreichbar ist, den Sie bereits täglich nutzen.

Was Sie dabei im Blick behalten sollten: Ein Agent mit wachsendem Gedächtnis ist auch ein Agent mit wachsendem Risikopotenzial. Je mehr Hermes über Sie weiß, desto wichtiger ist es, dass das System selbst sicher betrieben wird und dass Sie regelmäßig prüfen, welche Informationen gespeichert sind.

Claude Code: Der technische Projektmitarbeiter ​

Claude Code ist das Werkzeug, das am häufigsten unterschätzt wird, weil der Name nach Programmiersoftware klingt. Das stimmt nur zur Hälfte. Claude Code kann programmieren. Aber Claude Code ist vor allem ein Arbeitsagent, der Projekte versteht, Dateien liest und bearbeitet, Aufgaben plant und ausführt und dabei konsequent nach Freigabe fragt, bevor er etwas Irreversibles tut.

Die offizielle Dokumentation beschreibt Claude Code als Agenten, der Tests schreiben, Fehler beheben, Änderungen im Code durchführen, Git-Befehle ausführen, Commits vorbereiten und Pull Requests erstellen kann. Wer kein Programmierer ist, sollte diese Liste trotzdem lesen, weil hinter jedem Punkt eine allgemeine Fähigkeit steckt: Dateien lesen und verstehen, Änderungen vorschlagen, Änderungen ausführen, Versionskontrolle nutzen und Ergebnisse dokumentieren. Diese Fähigkeiten sind für viele Aufgaben nützlich, die nichts mit Programmierung zu tun haben.

Das Herzstück der Claude-Code-Konfiguration ist eine Datei namens CLAUDE.md. In dieser Datei hält der Agent fest, was er über ein Projekt wissen muss: Arbeitsstandards, Architekturentscheidungen, eingesetzte Werkzeuge, Formulierungsregeln und Checklisten, die bei jeder Aufgabe durchzugehen sind. Stellen Sie sich diese Datei wie eine Art Briefingdokument vor, das Claude Code zu Beginn jeder Sitzung liest, um sofort im richtigen Kontext zu sein.

Claude Code läuft auf mehreren Oberflächen: im Terminal, in VS Code und JetBrains (zwei verbreitete Entwicklungsumgebungen), auf dem Desktop, im Browser, in CI/CD-Systemen und in Chat-Workflows. Für Selbständige ohne technischen Hintergrund ist der Desktop-Zugang der einfachste Einstieg, weil er keine zusätzliche Softwareinstallation erfordert.

Das Sicherheitsmodell von Claude Code ist von Anfang an auf kontrollierten Zugriff ausgelegt. Der Agent beginnt mit Leserechten und fragt explizit nach, bevor er Dateien ändert, Tests ausführt oder Befehle startet. Er kann nur in dem Ordner schreiben, in dem er gestartet wurde, und in dessen Unterordnern. Wenn er mehr Zugriff braucht, fragt er nach. Das ist kein lästiger Einschränkung, sondern ein echtes Sicherheitsmerkmal, das dafür sorgt, dass unerwünschte Aktionen erkannt und gestoppt werden können, bevor sie Schaden anrichten.

Über MCP kann Claude Code auf externe Werkzeuge und Datenquellen zugreifen: Kalender, Datenbanken, Suchwerkzeuge, externe Dienste und mehr. MCP macht aus Claude Code nicht nur einen Dateibearbeiter, sondern einen Agenten, der in ein Ökosystem eingebettet ist.

Die typische Einsatzsituation für Claude Code sieht so aus: Sie arbeiten an einem konkreten Projekt, das Dateien, Strukturen und Aufgaben hat, die sich regelmäßig wiederholen. Sie wollen einen Agenten, der dieses Projekt kennt, Aufgaben darin eigenständig durchführt und dabei immer nachfragt, bevor er etwas Wichtiges ändert.

Codex: Der strukturierte Coding- und Automationsagent ​

OpenAI beschreibt Codex als Coding-Agent, der Code lesen, bearbeiten und ausführen kann. Im Vergleich zu Claude Code ist Codex stärker auf strukturierte Automatisierung und klare Genehmigungsprozesse ausgelegt.

Codex gibt es in zwei Varianten: als Kommandozeilenprogramm, das lokal auf Ihrem Rechner läuft, und als Cloud-Umgebung, die Aufgaben im Hintergrund in einer eigenen isolierten Umgebung ausführt. Die Kommandozeilenvariante läuft auf macOS, Windows und Linux und ist damit auf den meisten Computern direkt nutzbar. Die Cloud-Variante ermöglicht es, Aufgaben anzustoßen und weiterzuarbeiten, während Codex im Hintergrund läuft, ähnlich wie Clawbot, aber ohne eigenen Server.

Codex kann mit GitHub verbunden werden. Das bedeutet, dass der Agent Pull Requests erstellen, in bestehende Projekte einarbeiten und Änderungen über den Standard-Versionskontrollprozess einbringen kann. Für Selbständige, die Websites oder Software-Projekte betreuen, ist das ein erheblicher Zeitgewinn.

Was Codex besonders auszeichnet, ist das Approval-Modell, also das System der Genehmigungen. Die Dokumentation beschreibt verschiedene Modi: schreibgeschützt, workspace-write (schreiben im eigenen Arbeitsbereich), on-request (jede Aktion braucht eine Bestätigung) und danger-full-access (vollständiger Zugriff ohne Bestätigung). Für den Alltag empfiehlt sich workspace-write als sinnvoller Startpunkt: Der Agent kann Dateien im Arbeitsbereich bearbeiten und Befehle ausführen, fragt aber für alles, was über den Arbeitsbereich hinausgeht oder Netzwerkzugriff erfordert, nach Freigabe.

Die Konfiguration von Codex erfolgt über eine Datei namens AGENTS.md, die ähnlich wie die CLAUDE.md-Datei von Claude Code funktioniert: Sie enthält Arbeitsregeln, Berechtigungen, Hooks und Anweisungen, die der Agent bei jeder Sitzung liest.

Codex verfügt außerdem über eine automatische Überprüfungsfunktion, die eingehende Genehmigungsanfragen anhand von Risikokriterien bewertet: Datenabfluss, Zugriff auf Anmeldedaten, dauerhafte Sicherheitsabschwächung und destruktive Aktionen. Das ist eine nützliche Sicherheitsebene, die nicht ersetzt, dass Sie selbst prüfen, aber zumindest offensichtlich riskante Aktionen frühzeitig markiert.

Die typische Einsatzsituation für Codex sieht so aus: Sie wollen technische Aufgaben automatisieren, legen aber besonderen Wert auf klare Genehmigungsprozesse und möchten Aufgaben auch dann laufen lassen, wenn Sie nicht am Rechner sind, ohne eigenen Server zu betreiben.

MCP: Die Verbindungsschicht für echte Arbeit ​

Stellen Sie sich einen Assistenten vor, der alles versteht, aber nichts anfassen kann. Er kann Texte lesen, die Sie ihm zeigen, und Texte formulieren, aber er kann keine Dateien öffnen, keinen Kalender lesen, keine Datenbank abfragen und keine E-Mail senden. Das ist ein Chatbot ohne MCP.

Model Context Protocol, kurz MCP, ist der offene Standard, der Agenten aus dem Chatfenster herausführt und mit der Welt verbindet. Die offizielle Dokumentation verwendet dafür die Metapher eines USB-C-Anschlusses für KI-Anwendungen: Genauso wie USB-C ein universeller Standard ist, mit dem viele verschiedene Geräte verbunden werden können, ist MCP ein universeller Standard, mit dem Agenten viele verschiedene externe Systeme nutzen können.

In der Praxis bedeutet MCP: Ein Agent kann über einen MCP-Server auf lokale Dateien zugreifen, eine Datenbank abfragen, eine Suche ausführen, einen Rechner aufrufen, einen Kalender lesen, Workflows auslösen und spezialisierte Funktionen nutzen, die jemand anderes entwickelt und als MCP-Server bereitgestellt hat.

Für Claude Code und Codex ist MCP integriert. Das bedeutet, Sie können beide Werkzeuge mit MCP-Servern verbinden, ohne tiefes technisches Wissen zu haben. Viele nützliche MCP-Server existieren bereits und können für Kalender, E-Mail, GitHub, Tabellenkalkulationen, Datenbanken und andere Dienste genutzt werden.

MCP-Werkzeuge haben immer Namen, Beschreibungen und definierte Eingabeschemas. Das macht sie für Agenten transparent: Der Agent sieht, welche Werkzeuge verfügbar sind, was sie tun und welche Eingaben sie brauchen. Die MCP-Spezifikation empfiehlt ausdrücklich, dass die Benutzeroberfläche dem Nutzer klar zeigt, welche Werkzeuge dem Modell zur Verfügung stehen, und dass sensible Operationen vor der Ausführung bestätigt werden müssen.

MCP ist deshalb auch ein Sicherheitsthema, auf das Kapitel 3 ausführlicher eingeht. Je mehr Werkzeuge ein Agent nutzen kann, desto größer ist der potenzielle Schaden, wenn etwas schiefläuft. Deshalb gilt auch hier: Starten Sie mit wenigen, gut verstandenen MCP-Verbindungen und erweitern Sie nur dann, wenn Sie verstehen, was jedes Werkzeug tun darf und was nicht.

Drei Auswahlfragen vor der Installation ​

Bevor Sie ein Werkzeug installieren, beantworten Sie drei Fragen schriftlich. Das verhindert, dass Sie mehrere Systeme gleichzeitig halb einrichten und keines davon wirklich nutzen.

Erstens: Von wo aus soll die Aufgabe gestartet werden? Wenn Aufgaben unterwegs per Messenger gestartet werden sollen, spricht das für Clawbot oder Hermes. Wenn die Aufgabe in einem Projektordner liegt, sind Claude Code oder Codex näher dran. Wenn die Aufgabe auf GitHub endet, ist Codex besonders naheliegend.

Zweitens: Wie lange muss der Agent Kontext behalten? Für eine einzelne Projektaufgabe reicht ein gut gepflegtes Projektbriefing. Für einen persönlichen Assistenten, der über Monate hinweg besser werden soll, brauchen Sie Memory, Skills und eine Routine zur Pflege dieser Erinnerungen.

Drittens: Welche Rechte sind wirklich nötig? Ein Agent, der nur Texte zusammenfasst, braucht keine Schreibrechte. Ein Agent, der Dateien sortiert, braucht Zugriff auf genau diesen Ordner, nicht auf den ganzen Rechner. Ein Agent, der E-Mails vorbereitet, braucht zunächst nur Leserechte und darf Entwürfe erstellen, aber nicht selbst senden.

Ein realistischer Startpfad ​

Für die meisten Selbständigen ist der beste Start nicht ein großes Agenten-System, sondern ein kleiner, belastbarer Pfad:

  1. Beginnen Sie mit Claude Code oder Codex in einem klar begrenzten Projektordner.
  2. Legen Sie eine Projektanweisung an: Ziel, Stil, erlaubte Dateien, Stopregeln.
  3. Delegieren Sie eine ungefährliche Aufgabe, zum Beispiel eine Recherche, Gliederung oder Dateisortierung.
  4. Prüfen Sie das Ergebnis und notieren Sie, was gefehlt hat.
  5. Erst danach entscheiden Sie, ob ein persönlicher Assistent wie Hermes oder eine Fernsteuerung wie Clawbot sinnvoll ist.

So vermeiden Sie den häufigsten Fehler: zu früh zu viele Werkzeuge miteinander zu verbinden. Ein stabiles Werkzeug, das Sie verstehen, ist mehr wert als vier Agenten, die alle halb konfiguriert sind.

Welches Werkzeug für welche Aufgabe ​

Jetzt, wo Sie alle vier Werkzeuge kennen, kommt die wichtigste Frage: Welches Werkzeug passt wofür?

Eine einfache Faustformel hilft beim Einstieg.

Wenn Sie Aufgaben von unterwegs starten und im Hintergrund laufen lassen wollen, ist Clawbot die richtige Wahl. Es braucht technisches Grundwissen für die Einrichtung, gibt Ihnen dafür aber maximale Flexibilität und Unabhängigkeit.

Wenn Sie einen Agenten wollen, der über Wochen und Monate hinweg Ihre Arbeitsweise kennenlernt, wiederkehrende Routinen automatisch anstößt und über Ihren bevorzugten Messaging-Kanal erreichbar ist, ist Hermes die richtige Wahl.

Wenn Sie projektbezogene Aufgaben delegieren wollen, die Dateien, Strukturen und wiederkehrende Schritte umfassen, und wenn Sie dabei jederzeit die Kontrolle über einzelne Aktionen behalten wollen, ist Claude Code die richtige Wahl.

Wenn Sie technische Automatisierungen und strukturierte Arbeitsabläufe mit klaren Genehmigungsstufen bevorzugen und wenn GitHub oder andere Versionskontrollsysteme in Ihrer Arbeit eine Rolle spielen, ist Codex die richtige Wahl.

Diese vier Werkzeuge schließen sich gegenseitig nicht aus. In einem ausgereiften Setup arbeiten sie zusammen: Hermes als langfristiger Assistent und Gedächtnis, Claude Code für projektspezifische Aufgaben, Codex für technische Automatisierung und Clawbot als Fernbedienung, die alles erreichbar macht. Aber für den Anfang gilt: Beginnen Sie mit einem Werkzeug, das zu Ihrer wichtigsten Aufgabe passt. Und bleiben Sie dabei, bis Sie es wirklich kennen.

Im nächsten Kapitel lernen Sie, wie Sie diese Werkzeuge sicher betreiben. Denn je leistungsfähiger ein Agent ist, desto wichtiger ist es, seine Grenzen zu verstehen.
