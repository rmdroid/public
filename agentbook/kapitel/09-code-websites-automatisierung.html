Kapitel 9: Code, Websites und technische Automatisierung ​

Kleine Automatisierungen mit großer Wirkung ​

Sie haben eine Tabelle mit Kundendaten im falschen Format. Jemand müsste das konvertieren. Sie haben eine Website, auf der ein Text geändert werden soll, aber Sie wissen nicht, wo Sie anfangen müssen. Sie haben ein kleines Problem mit einem Skript, das eigentlich automatisch Berichte erstellen sollte, aber es macht es nicht mehr. Und Sie haben eine Idee für eine kleine Automatisierung, die Ihnen jede Woche 20 Minuten sparen würde, wenn jemand sie umsetzen könnte.

Früher hätten Sie für all das entweder einen Entwickler gebraucht oder Sie hätten es selbst gelernt. Beides kostet Zeit und Geld. Heute können Claude Code und Codex für viele dieser Aufgaben eingesetzt werden, auch wenn Sie kein Programmierkenntnisse haben.

Dieses Kapitel erklärt, wie das funktioniert, was realistisch ist, was die Grenzen sind, und wie Sie technische Agentenaufgaben so formulieren und begleiten, dass die Ergebnisse tatsächlich nützlich sind.

Die wichtige Erwartungskorrektur ​

Bevor wir ins Praktische gehen, eine ehrliche Einschätzung der aktuellen Lage.

Claude Code und Codex sind 2026 die leistungsfähigsten Coding-Agenten, die öffentlich verfügbar sind. Unabhängige Tests zeigen, dass Claude Code bei Softwareentwicklungsaufgaben eine höhere Trefferquote hat, während Codex im Terminal-Bereich und bei der Verarbeitung langer Aufgaben effizienter ist und deutlich weniger Ressourcen verbraucht. Für Selbständige, die beide Werkzeuge testen möchten, lohnt sich die kombinierte Nutzung: Claude Code für präzise, kontextreiche Aufgaben, Codex für größere autonome Arbeitsaufträge im Hintergrund.

Was diese Werkzeuge für Nicht-Programmierer leisten können, hat sich gegenüber 2024 erheblich verbessert. Sie können einfache Skripte selbständig schreiben, Daten konvertieren, Fehler in bestehendem Code erklären und beheben sowie Dokumentation erstellen. Was sie nicht können: Sie werden keine komplexen Software-Architekturen ohne menschliche Begleitung fehlerfrei umsetzen, und sie können Fehler machen, die Sie als Nicht-Programmierer nicht sofort erkennen.

Die richtige Grundhaltung für dieses Kapitel ist deshalb: Claude Code und Codex als sehr gute technische Assistenten behandeln, die schnell und breit aufgestellt sind, aber deren Arbeit Sie sorgfältig prüfen, bevor sie produktiv eingesetzt wird.

Dateikonvertierung und Datenverarbeitung ​

Eine der zuverlässigsten Aufgaben für Coding-Agenten ist das Umwandeln von Dateien von einem Format in ein anderes. Diese Aufgabe ist klar definiert, das Ergebnis ist leicht prüfbar und das Risiko ist überschaubar.

Typische Konvertierungsaufgaben für Selbständige sind: CSV-Dateien in strukturierte Tabellen umwandeln, mehrere PDF-Dokumente in durchsuchbare Textdateien konvertieren, Excel-Tabellen aus einem veralteten Format in ein aktuelles überführen, Kundendaten aus einem Export-Format in ein anderes importierbares Format übersetzen und JSON-Daten lesbar formatieren oder in Tabellen umwandeln.

Für all diese Aufgaben ist Claude Code oder Codex gut geeignet. Der Workflow ist einfach: Sie beschreiben, was Sie haben und was Sie brauchen. Der Agent schreibt ein kurzes Skript, erklärt, was es tut, und führt es aus. Sie prüfen das Ergebnis, und wenn es stimmt, speichern Sie das Skript als Skill für zukünftige ähnliche Aufgaben.

Dabei gilt: Je klarer Sie die Aufgabe beschreiben, desto besser das Ergebnis. Nicht "Konvertiere diese Datei", sondern "Diese CSV-Datei hat Spalten A, B und C. Ich brauche sie als Excel-Tabelle mit diesen drei Spalten in dieser Reihenfolge und mit diesen Datumsformaten."

Fehlersuche und Erklärung ​

Eine besonders wertvolle Fähigkeit von Claude Code und Codex für Nicht-Programmierer ist die Fehlersuche und -erklärung. Wenn Sie ein Skript oder eine Automatisierung nutzen, die plötzlich nicht mehr funktioniert, und Sie keine Ahnung haben, was das Problem ist, kann ein Agent Ihnen in verständlicher Sprache erklären, was schiefgelaufen ist und wie es behoben werden kann.

Statt vor einer kryptischen Fehlermeldung zu sitzen und stundenlang in Foren zu suchen, übergeben Sie dem Agenten das Skript und die Fehlermeldung und bitten ihn: "Erkläre mir, was dieser Fehler bedeutet, warum er aufgetreten ist und wie ich ihn behebe. Erkläre es so, dass jemand ohne Programmierkenntnisse es versteht."

Die Antwort wird in den meisten Fällen eine verständliche Erklärung und einen konkreten Lösungsvorschlag enthalten. Sie prüfen die vorgeschlagene Lösung, fragen nach, wenn etwas unklar ist, und setzen sie mit Begleitung des Agenten um.

Kleine Skripte für wiederkehrende Aufgaben ​

Viele Selbständige haben wiederkehrende Aufgaben, die manuell fünf bis zehn Minuten dauern und für die ein kleines Skript sie auf Knopfdruck erledigen würde. Das Umbenennen aller Dateien in einem Ordner nach einem bestimmten Schema, das automatische Zusammenfassen aller Texte in einem Ordner in eine einzige Datei, das regelmäßige Erstellen einer Zusammenfassung aus mehreren Projektnotizen, oder das Exportieren bestimmter Daten aus einer Tabelle in ein fixes E-Mail-Format.

Für solche Aufgaben lohnt sich die Investition von 20 bis 30 Minuten, um gemeinsam mit Claude Code ein Skript zu entwickeln. Das Resultat ist ein Werkzeug, das Sie jederzeit wiederverwenden können und das die Aufgabe jedes Mal in Sekunden erledigt.

Ein praktischer Workflow für das Entwickeln solcher Skripte sieht so aus. Erstens: Beschreiben Sie die Aufgabe so genau wie möglich, mit Beispieleingabe und gewünschter Ausgabe. Zweitens: Lassen Sie den Agenten ein Skript schreiben und Ihnen erklären, was es Schritt für Schritt tut. Drittens: Testen Sie das Skript zunächst mit einer kleinen Testmenge, nie sofort mit allen Produktionsdaten. Viertens: Prüfen Sie das Ergebnis sorgfältig. Fünftens: Wenn alles stimmt, speichern Sie das Skript und dokumentieren Sie in einem Kommentar, was es tut und wann Sie es einsetzen.

Der dritte Schritt, das Testen mit kleinen Mengen, ist besonders wichtig. Ein Skript, das 500 Dateien auf einmal bearbeitet, und das dabei einen Fehler macht, richtet mehr Schaden an als eines, das fünf Testdateien verarbeitet und dabei zeigt, dass es korrekt funktioniert.

Website-Anpassungen: Texte, Formatierungen, kleine Änderungen ​

Viele Selbständige betreiben eine eigene Website, die gelegentlich aktualisiert werden muss. Ein Text auf der Angebotsseite soll geändert werden. Ein neues Projekt soll ins Portfolio. Die Kontaktseite braucht eine neue Telefonnummer. Das Impressum muss aktualisiert werden.

Für technisch nicht versierte Selbständige sind diese Änderungen oft eine Hürde, weil sie ein Content-Management-System bedienen müssen, das sie nicht gut kennen, oder weil die Website direkt in HTML oder CSS geschrieben ist und jede Änderung Grundkenntnisse erfordert.

Claude Code kann bei einfachen Website-Änderungen helfen, wenn Sie ihm Zugriff auf die Dateien der Website geben. Sie sagen, was Sie ändern wollen, er sucht die richtige Stelle im Code, erklärt, was er ändern wird, und macht die Änderung nach Ihrer Bestätigung.

Für komplexere Änderungen, zum Beispiel das Hinzufügen einer neuen Seite mit einer bestimmten Struktur, das Optimieren der Ladegeschwindigkeit oder das Anpassen des Designs, braucht es etwas mehr Begleitung, aber auch hier gilt: Der Agent erklärt jeden Schritt, und Sie entscheiden, ob er ihn ausführen soll.

Wichtiger Sicherheitshinweis für Website-Arbeit: Bevor Sie einen Agenten auf Ihre Website-Dateien loslassen, erstellen Sie eine Sicherungskopie. Das ist der erste Schritt, immer, ohne Ausnahme. Eine Änderung, die die Website unbrauchbar macht, ist reversibel, wenn Sie eine Sicherungskopie haben. Ohne Sicherungskopie wird aus einem kleinen Problem ein großes.

GitHub: Versionskontrolle für Nicht-Programmierer ​

GitHub ist eine Plattform, auf der Code und Dokumente versioniert gespeichert werden. Versionierung bedeutet: Jede Änderung wird gespeichert, Sie können jede frühere Version wiederherstellen und Sie sehen genau, wer wann was geändert hat.

Für Selbständige, die Claude Code oder Codex für technische Projekte nutzen, lohnt sich die Verbindung mit GitHub, auch ohne Programmierkenntnisse, aus einem einzigen Grund: Sie können jede Änderung rückgängig machen.

Codex hat eine direkte GitHub-Integration, die das Erstellen von sogenannten Pull Requests ermöglicht. Das sind Änderungsvorschläge, die geprüft und genehmigt werden müssen, bevor sie wirksam werden. Das ist das technische Äquivalent des Freigabeprozesses, den dieses Buch für alle kritischen Agentenaktionen empfiehlt: Erst vorschlagen, dann prüfen, dann umsetzen.

Für den Einstieg reichen drei grundlegende GitHub-Aktionen: Dateien speichern und kommentieren, Änderungen rückgängig machen und verschiedene Versionen eines Projekts nebeneinander halten. Claude Code und Codex können Ihnen bei allen drei Aktionen helfen, ohne dass Sie die Kommandozeilenbefehle dahinter kennen müssen.

Dokumentation schreiben und aktuell halten ​

Eine regelmäßig vernachlässigte, aber wichtige Aufgabe für Selbständige mit technischen Projekten oder Automatisierungen ist die Dokumentation. Wenn ein Skript, ein Workflow oder eine Website-Konfiguration nicht dokumentiert ist, ist sie nach wenigen Monaten auch für Sie selbst unverständlich.

Claude Code kann bestehenden Code und Skripte lesen und automatisch eine verständliche Dokumentation dafür schreiben: Was macht das Skript? Welche Eingaben braucht es? Was ist das Ergebnis? Was kann schiefgehen? Wann sollte es verwendet werden?

Diese Dokumentation können Sie in einer einfachen Textdatei neben dem Skript speichern. Sie ist kein Aufwand für Sie, weil der Agent sie schreibt. Und sie ist unverzichtbar für Ihr zukünftiges Ich, das sich in sechs Monaten nicht mehr erinnert, warum das Skript genau so geschrieben wurde.

CI/CD und Automations: Die nächste Stufe ​

Für Selbständige, die regelmäßig mit Software-Projekten oder technischen Automationen arbeiten, gibt es eine weitere Ebene, die Claude Code und Codex erschließen können: CI/CD, also die automatische Ausführung von Tests und Prozessen, wann immer eine Änderung gemacht wird.

CI steht für Continuous Integration, also die automatische Prüfung, ob eine neue Änderung das Projekt nicht beschädigt hat. CD steht für Continuous Deployment, also die automatische Veröffentlichung von geprüften Änderungen.

Für Selbständige, die eine Website oder eine Webanwendung betreiben, bedeutet das in der Praxis: Wenn Sie eine Änderung machen und sie hochladen, prüft ein automatischer Prozess, ob die Website noch läuft, ob wichtige Seiten noch erreichbar sind und ob die Änderung keine unbeabsichtigten Nebeneffekte hat. Erst wenn alles in Ordnung ist, wird die Änderung live geschaltet.

Claude Code und Codex können solche Prüfprozesse einrichten und konfigurieren. Für den Anfang reicht ein einfacher Test, der prüft, ob die wichtigsten Seiten der Website nach einer Änderung noch laden. Das ist ein Sicherheitsnetz, das auch technisch nicht versierten Selbständigen nützt und das mit Agentenunterstützung in einer Stunde eingerichtet ist.

Ein Wort zur aktuellen Leistungsrealität 2026 ​

Basierend auf unabhängigen Vergleichstests aus dem Jahr 2026 lässt sich folgendes festhalten. Claude Code erreicht bei Software-Entwicklungsaufgaben eine höhere Qualität, nutzt aber deutlich mehr Token und stößt bei intensiver Nutzung schneller an Nutzungsgrenzen. Codex ist in der täglichen Dauerbenutzung konsistenter, verbraucht beim gleichen Umfang etwa viermal weniger Token und ist besonders stark bei Terminal- und DevOps-Aufgaben.

Für Selbständige, die beide Werkzeuge einsetzen möchten, empfiehlt sich eine Arbeitsteilung: Claude Code für Aufgaben, bei denen Präzision und Kontext wichtig sind, also Einzeldateien, komplexe Erklärungen und Architekturentscheidungen, und Codex für Aufgaben, die im Hintergrund laufen, also das Ausführen größerer Umbauarbeiten, GitHub-Aktionen und zeitintensive Automatisierungen.

Diese Empfehlung kann sich schnell ändern, weil beide Werkzeuge aktiv weiterentwickelt werden. Prüfen Sie aktuelle Vergleichstests vor einer längerfristigen Investitionsentscheidung, denn der Abstand zwischen den Werkzeugen wird kleiner, und neue Versionen verändern die Stärken regelmäßig.

Die wichtigste Regel für technische Agentenarbeit ​

Dieses Kapitel endet mit der einen Regel, die über alles andere hinausgeht: Testen Sie in einer sicheren Umgebung, bevor Sie in einer produktiven Umgebung arbeiten.

Ein Skript, das Dateien umstrukturiert, sollte zuerst an fünf kopierten Testdateien getestet werden, nicht an den 500 originalen. Eine Website-Änderung sollte zuerst auf einer lokalen Kopie oder einem Testserver geprüft werden, nicht live. Eine Automatisierung, die regelmäßig Daten verarbeitet, sollte einen Durchlauf mit synthetischen Testdaten hinter sich haben, bevor sie echte Kundendaten anfasst.

Diese Regel kostet immer etwas Zeit. Aber sie verhindert Szenarien, die weit mehr Zeit kosten: verlorene Daten, defekte Websites, fehlerhafte Ausgaben, die sich in mehrere Dokumente weitergeschrieben haben.

Claude Code und Codex sind mächtige Werkzeuge. Ihre Stärke liegt in der Kombination von technischer Breite und Dialogfähigkeit. Sie können mit ihnen über jeden Schritt sprechen, nachfragen, korrigieren und schrittweise besser werdende Ergebnisse erarbeiten. Dieses Potenzial entfaltet sich am besten, wenn Sie ihr Urteilsvermögen ergänzt, nicht ersetzt.
